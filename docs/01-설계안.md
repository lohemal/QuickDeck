# QuickDeck 설계안

하드웨어 Stream Deck 이 없어도 쓸 수 있는 **화면형 컨트롤 덱**. 자주 쓰는 사이트·프로그램·파일·폴더·Windows 기능·검색을 버튼으로 등록하고, 마우스 클릭이나 `전역 단축키 → 실행키` 로 빠르게 실행한다.

이 문서는 프로젝트의 기준 문서다. 구조나 데이터 모델이 바뀌면 여기를 먼저 고친다.

## 1. 기술 스택과 원칙

| 항목 | 선택 | 이유 |
|---|---|---|
| 셸 | Tauri 2 | 작은 설치 파일, Rust 로 Windows API 직접 접근, GitHub Release 업데이터 플러그인 |
| UI | React 18 + TypeScript + Vite 6 | CSS 변수 기반 반응형 처리에 유리, 다른 프로젝트와 도구 통일 |
| 상태 | zustand | 보일러플레이트 없이 스토어 하나로 덱·설정·저장 상태 관리 |
| 저장 | JSON 파일 1개 | 데이터가 작고(버튼 수십 개), 사람이 읽고 백업하기 쉬움. DB 불필요 |
| 대상 | Windows 전용 | WebView2·Win32 API 를 전제로 단순화 |

원칙

- **로컬 전용**: 서버·계정 없음. 모든 데이터는 `%APPDATA%\kr.lohemal.quickdeck\` 아래.
- **구조의 단일 기준은 프론트엔드**: 저장 파일 스키마·마이그레이션은 `src/model` 이 소유한다. Rust 는 JSON 텍스트를 읽고 쓰기만 한다. Rust 가 타입으로 아는 것은 *실행할 동작(Action)* 만이다.
- **애니메이션은 독립 레이어**: 핵심 흐름(표시 → 실행 → 숨김)은 애니메이션 없이 완결된다. 애니메이션은 이후 `features/animation` 으로 얹되 설정으로 완전히 끌 수 있다.
- **배포를 방해하지 않기**: 바이너리 이름·identifier 는 ASCII 로 고정. 업데이터는 플러그인·권한·`createUpdaterArtifacts` 만 켜면 붙도록 설정 형태를 다른 프로젝트와 맞춰 둔다.

## 3. 데이터 모델

### 3.1 저장 파일 `quickdeck.json`

```ts
AppData {
  schemaVersion: 1
  settings: Settings
  decks: Deck[]          // 지금은 1개. 여러 덱(프로필)을 위해 배열
  activeDeckId: string
}
```

- 읽기: Rust 가 텍스트 반환 → `JSON.parse` → `migrate()` → 실패 시 기본값으로 시작.
- 쓰기: 변경 후 400ms 디바운스 → `JSON.stringify` → Rust 가 `.json.tmp` 에 쓰고 rename.
- 스키마 변경 절차: `SCHEMA_VERSION` 증가 → `migrate()` 에 `if (v === n) {...; v = n+1}` 단계 추가.

### 3.2 덱과 버튼

```ts
Deck { id, name, layout: { columns, rows }, buttons: DeckButton[] }

DeckButton {
  id: string                       // crypto.randomUUID()
  position: { row, col }           // 0 기준. 격자 밖 버튼은 setLayout 시 버려진다
  name: string
  action: Action                   // 아래 3.3
  icon: IconRef                    // 아래 3.4
  hotkey: string | null            // 단일 키 "1"~"0", "A"~"Z"
  display: 'icon' | 'text' | 'icon-text'   // 기본 icon-text
}
```

- 버튼은 **위치 배열이 아니라 목록**으로 저장한다. 빈 슬롯은 "그 위치에 버튼이 없음" 으로 표현되므로 행/열이 바뀌어도 데이터가 어긋나지 않는다.
- 기본 실행키는 `keys.ts` 가 실제 키보드 행(`1234567890` / `QWERTYUIOP` / `ASDFGHJKL` / `ZXCVBNM`)에서 위치로 뽑아 준다. 4×3 이면 정확히 `1234 / QWER / ASDF`.

### 3.3 동작 `Action` (판별 유니온, `type` 필드)

| type | 필드 | 실행 주체 |
|---|---|---|
| `website` | `url`, `browser: default\|edge\|chrome` | Rust |
| `program` | `path`(exe/.lnk), `args?` | Rust |
| `file` | `path` | Rust |
| `folder` | `path` | Rust |
| `system` | `command: SystemCommand` (15종) | Rust |
| `search` | `engine`(프리셋 id 또는 사용자 정의 id), `browser` | 프론트가 URL 생성 후 `website` 로 Rust 호출 |

- 위험 기능 집합 `DANGEROUS_SYSTEM_COMMANDS`(절전·로그아웃·재시작·종료)는 실행 전 확인창 대상.
- 검색엔진: 프리셋(Google/Naver/Bing)은 코드에, 사용자 정의는 `settings.customSearchEngines[{id,name,urlTemplate}]` 에. `{query}` 치환.
- **새 동작 추가 절차**: `model/action.ts` 유니온 → `features/actions/registry.ts` 항목 → (Rust 실행 필요 시) `model.rs` variant + `actions/` 구현. 타입이 `Record<ActionType, …>` 이라 registry 누락은 컴파일 오류가 된다.

### 3.4 아이콘 `IconRef`

```ts
{ kind: 'none' }
{ kind: 'builtin',   name: string }   // 내장 아이콘 세트 (이후 제작)
{ kind: 'extracted', file: string }   // exe/lnk 에서 추출 → 앱 데이터 폴더 icons/ 에 PNG 저장
{ kind: 'image',     file: string }   // 사용자 이미지 → 검증·리사이즈 후 icons/ 에 저장
```

이미지 원본 경로를 저장하지 않고 **앱 데이터 폴더에 복사한 파일명**만 저장한다. 원본이 지워져도 버튼이 깨지지 않고, 등록 시점에 크기·손상 검증을 강제할 수 있다.

### 3.5 설정 `Settings` (스키마 v2)

```ts
window: {
  alwaysOnTop, autoStart, hideAfterRun, closeToTray: boolean
  showAt: 'cursor-monitor' | 'last-position'      // 호출 위치
  lastBounds: { x, y, width, height } | null       // x/y 물리 px(절대 좌표), width/height 논리 px(DPI 무관)
}
hotkey: { enabled, accelerator }                     // 기본 'Ctrl+Shift+Space' (DEFAULT_HOTKEY 한 곳, 2026-09-19 변경)
defaultBrowser, defaultSearchEngine, customSearchEngines[{ id, name, urlTemplate }], animationEnabled
```

- v1 → v2: `rememberSize/rememberPosition` 제거(크기는 항상 기억, 위치는 showAt 이 대신), `showAt` 추가, `lastBounds` 는 단위를 새로 정의해 null 로 시작. `migrate()` 가 변환하고 버튼 데이터는 그대로 둔다.
- 창 크기·위치는 Rust 가 사용자의 Moved/Resized 를 500ms 디바운스해 `deck-bounds` 로 알리고 프론트가 저장한다. 프로그램이 창을 배치하는 동안(show)의 이동은 기록하지 않는다.
- 덱 `layout` 을 줄이면 격자 밖 버튼은 데이터로 보존된다(`hiddenButtons`). 다시 늘리면 같은 자리에 돌아온다. 설정 화면에서 명시적으로 지울 수 있다. 격자 밖 버튼은 실행키로 실행되지 않고, 실행키 중복 검사에는 포함된다(복원 시 충돌 방지).
- 행/열 범위: 열 2~10, 행 1~6 (`LAYOUT_LIMITS`).

## 4. 반응형 규칙

`useDeckMetrics(container, layout)` 하나가 모든 치수를 결정한다.

```
cell  = min( (W - gap·(cols-1)) / cols , (H - gap·(rows-1)) / rows )   // 정사각형
gap   = clamp(cell × 0.08, 4, 20)
icon  = cell × 0.42
font  = clamp(cell × 0.13, 9, 22)
badge = clamp(cell × 0.10, 8, 14)
radius= cell × 0.12,  padding = cell × 0.08
compact = cell < 34   → 이때만 텍스트를 포기하고 아이콘만
```

값은 CSS 변수(`--cell --gap --icon --font --badge-font --radius --pad`)로 격자에 주입되고, 버튼·배지·빈 슬롯 CSS 는 이 변수만 참조한다. 즉 **크기 로직은 TS 한 곳, 모양은 CSS 한 곳**. 긴 이름은 `text-overflow: ellipsis`(텍스트만 표시일 때는 2줄 clamp).

**표시 방식 원칙**: 사용자가 버튼마다 고른 표시 방식(아이콘만/텍스트만/아이콘+텍스트)은 창이 작아져도 바꾸지 않는다. 글자 크기 축소와 말줄임으로 대응하고, 글자 한 줄조차 들어가지 않는 `compact` 크기에서만 아이콘만 그린다.

## 4.1 버튼 편집 흐름

- 빈 슬롯 클릭 → `ButtonEditor`(mode: create). 우클릭 메뉴 → 편집(mode: edit, 현재 값 채움) / 삭제(확인창).
- 폼은 `ButtonDraft` 라는 작업 사본을 다룬다. 동작 종류별 필드를 따로 보관해 종류를 바꿔도 입력이 남고, 저장 시 선택된 종류만 `Action` 으로 뽑는다(`draftToButton`).
- 이름 자동 제안: `nameEdited` 가 false 인 동안 파일·폴더·프로그램 선택이나 시스템 기능 선택이 이름을 채운다. 사용자가 한 글자라도 입력하면 자동 제안이 멈춘다.
- 실행키: 생성 시 슬롯의 기본키(`defaultHotkeyFor`)를 제안하되 이미 쓰이면 비운다. 검증은 `validateDraft` 한 곳(`findHotkeyOwner` 로 중복 소유자 표시).
- 선택창은 `ipc/dialog.ts` 가 감싼다. `.lnk` 는 대상으로 풀리지 않고 경로 그대로 돌아온다(실측).

## 4.2 검색 팝오버

- App 이 `search: { button, anchor }` 상태를 가진다. 검색 버튼 클릭 → 같은 버튼이면 닫고, 다른 버튼이면 그쪽으로 옮긴다. 일반 버튼 클릭·빈 슬롯 클릭·우클릭·편집/삭제는 모두 팝오버를 닫는다.
- `SearchPopover` 는 `position: fixed` 로 덱 위에 겹쳐 뜨므로 격자 레이아웃에 영향이 없다. 위치는 `computePopoverPosition(anchorRect, popoverSize, viewport)` 가 정한다: 아래 기본, 아래가 모자라면 위, 둘 다 모자라면 넓은 쪽 + 창 안으로 clamp. 좌우도 margin 안으로 clamp.
- 위치는 `useLayoutEffect` 에서 DOM 에 직접 적용해 첫 프레임부터 제자리에 보이고, 그 자리에서 곧바로 `input.focus()` 한다. 창 크기 변경은 `resize` + 다음 프레임 재계산, 격자 재배치는 앵커 `ResizeObserver` 로 따라간다.
- 닫힘: Esc / 바깥 mousedown(캡처 단계; 앵커 자신은 제외) / 검색 성공 / 다른 버튼. 닫힐 때 포커스가 body 로 떨어지면 검색 버튼으로 되돌린다(바깥 클릭은 클릭한 곳이 포커스를 가지므로 제외).
- 접근성: 버튼에 `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`; 팝오버는 `role="search"` + 입력란 `aria-label`. 빈 검색어 Enter 는 `aria-invalid` 표시만 하고 유지한다.
- 실행: `runAction(action, { settings, query })` → `findSearchEngine` → `buildSearchUrl`(encodeURIComponent) → `website` 동작으로 Rust `web::open_url`. 검색 전용 브라우저 코드는 없다.

## 4.3 호출·실행키·숨김 흐름

```
앱 시작: 창은 visible:false → 프론트 load → applyWindowPrefs(크기·위치·정책) → launch_info
  → --autostart 로 시작됐으면 트레이 대기 / 아니면 show_deck
전역 단축키 (RegisterHotKey, tauri-plugin-global-shortcut; 값은 Settings.hotkey)
  → window::toggle: 보이고 활성이면 hide / 아니면 show
  → show: showAt=last-position 이고 lastBounds 가 현재 모니터 안이면 그 자리(작업 영역 안으로 clamp)
          아니면 cursor_position → monitor_from_point → work_area 중앙(물리 px). 크기는 lastBounds 논리 크기를 항상 복원
          → show → (DPI 바뀌면) 재배치 → set_focus
  → emit deck-visibility(true) → 프론트 window.focus(), 입력 요소 blur
키 입력 (window keydown)
  → Esc: 다이얼로그(자체 처리) > 입력 요소 blur > 팝오버 닫기 > 메뉴 닫기 > hide_deck
  → 그 외: shouldHandleDeckHotkey 통과 → findButtonForEvent(code 우선) → handleRun(button, 버튼 요소)
      검색 버튼 → 팝오버 열기(마우스와 같은 경로) / 그 외 → 위험 확인 → runAction
  → 성공 && shouldHideAfterRun(button, settings) → hide_deck  (실패 시 유지 + 오류 안내)
숨김 (deck-visibility false) → 팝오버·메뉴 정리 → 다음 호출은 빈 상태
X 버튼 → CloseRequested → prefs.close_to_tray ? prevent_close + hide : 종료
트레이: 열기 = show_at_cursor, 종료 = app.exit(0)
```

- 단위: Rust 창 배치는 **물리 px 만** 쓴다(`PhysicalPosition`, `outer_size`, `work_area`). 논리 단위와 섞지 않는다.
- 실행키 판정은 `event.code` 기준이라 한글 IME 상태와 무관하다. 스캔코드 없이 주입된 입력(code="")만 ASCII `key` 로 대체한다.
- 애니메이션 레이어는 `deck-visibility` 이벤트를 구독해 연출을 얹는 방식으로 붙인다. 창 표시/숨김·실행 로직은 애니메이션을 모른다.

## 5. IPC 경계

| 명령 | 방향 | 내용 |
|---|---|---|
| `app_info` | → | 버전, 데이터 폴더 |
| `load_app_data` | → | JSON 텍스트 또는 null |
| `save_app_data(json)` | ← | 검증 후 원자적 저장 |
| `execute_action(action)` | ← | Rust 실행기 (`actions/`). 성공 시 `()`, 실패 시 아래 오류 객체 |
| `show_deck` / `hide_deck` / `toggle_deck` | ← | 창 표시·숨김 (`window.rs`) |
| `apply_hotkey(enabled, accelerator)` | ← | 전역 단축키 재등록. 실패 시 직전 단축키 복구 + 사용자 문구 오류 |
| `apply_window_prefs(prefs)` | ← | 항상 위 · X 버튼 정책 · 호출 위치 · 마지막 bounds |
| `launch_info` | → | `--autostart` 로 시작됐는지 |
| `deck_placement_info` | → | 진단: 커서·모니터·작업영역·창 좌표(물리 px)·논리 크기·prefs |
| 이벤트 `deck-visibility` | → | 창이 보이거나 숨겨질 때 (bool) |
| 이벤트 `deck-bounds` | → | 사용자가 창을 옮기거나 크기를 바꾼 뒤 (디바운스) |
| 플러그인 autostart | ↔ | `enable/disable/isEnabled` (HKCU Run, 인자 `--autostart`) |

오류는 `AppError` → `{ message, detail }` 객체로 직렬화되어 `invoke` reject 로 전달된다. `message` 는 사용자에게 그대로 보여줄 한국어 문장, `detail` 은 경로·Win32 코드 등 디버깅 정보다(프론트는 `ipc/errors.ts` 의 `toUserError` 로 읽어 콘솔에만 남긴다).

### 5.1 실행 흐름

```
버튼 클릭 → App.handleRun
  ├─ dangerPromptFor(action) 있음 → ConfirmDialog(취소 / 로그아웃·다시 시작·종료) → 확인 시에만 ↓
  └─ runAction(action, ctx)  (features/actions/execute.ts)
       ├─ search: 검색어 없으면 'unavailable' 안내 (Rust 호출 없음) / 있으면 URL 만들어 website 로
       └─ 그 외: invoke('execute_action') → actions::execute
            ├─ Website → web::open_url        (기본: ShellExecuteW / Edge·Chrome: exe 탐색 후 Command)
            ├─ Program/File/Folder → shell::*   (존재 확인 → ShellExecuteW; .lnk 는 셸이 풂)
            └─ System → system::run             (SendInput / LockWorkStation / SetSuspendState / shutdown.exe / URI)
성공: 조용히 끝남. 실패: 붉은 Notice 에 message, 콘솔·Rust 로그에 detail.
```

## 6. 의도적으로 하지 않은 것

- ts-rs 등 타입 공유 도구: Rust 가 아는 타입이 Action 하나라 수동 미러 + 단위 테스트로 충분.
- SQLite: 데이터 규모에 비해 과함. JSON 이 백업·이식에도 유리.
- 플러그인 시스템·동적 로딩: 동작 종류는 코드에 열거(registry)하는 것이 타입 안정성과 단순함에서 낫다.
