# QuickDeck 개발 로드맵

각 단계는 그 자체로 실행·확인 가능한 상태로 끝나야 한다. 순서는 "먼저 실제로 쓸 수 있게, 그 다음 편하게, 마지막에 예쁘게".

## P0 — 기틀 (완료, 2026-09-17)

- Tauri 2 + React + TS 프로젝트, 폴더 구조, 데이터 모델, IPC 경계
- 4×3 덱 격자, 빈 슬롯, 임시 버튼, 반응형 치수 계산
- `quickdeck.json` 자동 저장·복원, 스키마 버전·마이그레이션 틀
- Rust 실행기 디스패치 골격 (모두 NotImplemented)

## P1 — 동작 실행기 (Rust) (완료, 2026-09-17)

- `actions/web.rs` 기본 브라우저는 `ShellExecuteW("open", url)`. Edge/Chrome 은 레지스트리 App Paths(HKCU→HKLM→WOW6432Node) 와 일반 설치 위치에서 exe 를 찾아 `Command::new(exe).arg(url)`. 없으면 `BrowserNotFound`
- `actions/shell.rs` `ShellExecuteW` 래퍼(COM 초기화한 전용 스레드). exe/.lnk/파일/폴더 모두 이 경로. 존재 확인을 먼저 해 사용자용 오류로 바꾼다. 인자는 Windows 인용 규칙으로 합침(단위 테스트)
- `actions/system.rs` 미디어·볼륨 `SendInput`, 잠금 `LockWorkStation`, 절전 `SetSuspendState(false)`, 로그아웃/재시작/종료 `shutdown.exe /l | /r /t 0 | /s /t 0`(`power_command` 로 분리해 실행 없이 테스트), 탐색기 `explorer.exe`, 설정 `ms-settings:`, 작업 관리자 `taskmgr.exe`, 캡처 `ms-screenclip:`(실패 시 `snippingtool.exe`)
- 오류: `AppError` 가 `{ message, detail }` 로 직렬화. message 는 그대로 표시, detail 은 콘솔·Rust 로그
- 프론트: `dangerous.ts` 가 `DANGEROUS_SYSTEM_COMMANDS`(로그아웃·재시작·종료) 확인창 문구·버튼명 제공. 성공 시 알림 없음, 실패 시만 붉은 안내. 검색 버튼은 검색어 없이는 Rust 로 보내지 않고 안내만
- 실측 메모: 이 개발 PC 에는 Chrome 이 없어 "찾을 수 없음" 경로만 확인. 잠금·절전·전원 기능은 실행 직전 코드까지만 검증(사용자 수동 확인 예정)

## P2 — 버튼 편집 UI (완료, 2026-09-17)

- 빈 슬롯 클릭 → 추가 다이얼로그, 우클릭 → 편집·삭제(확인창). 추가·편집은 같은 화면(`features/editor`)
- 동작 종류별 입력: 웹사이트(URL 검사·정규화, 브라우저), 프로그램/파일/폴더(`tauri-plugin-dialog` 선택창, 이름 자동 제안), 시스템(목록 선택 → 이름 제안), 검색(엔진·브라우저)
- 표시 방식 3종, 실행키(슬롯 기본키 제안, 중복 시 소유 버튼 이름 표시, 없음 가능)
- 반응형 원칙 변경: 사용자가 고른 표시 방식을 지키고, 셀 34px 미만에서만 아이콘만 표시
- `sampleButtons.ts` 삭제. `DevBar` 는 행/열 변경·치수 확인용으로 설정 화면이 생길 때까지 유지
- 남긴 것: 버튼 위치 이동(드래그), 아이콘 선택(P5), 시스템 기능 편집 시 위험 기능 안내

## P3 — 검색 버튼 (완료, 2026-09-17)

- `features/search/SearchPopover.tsx` 검색 버튼에 붙는 fixed 팝오버. 열리면 입력란 즉시 포커스, Enter 검색·Esc 닫기·바깥 클릭 닫기·다른 검색 버튼으로 이동. 매번 새로 마운트되어 검색어는 빈 상태로 시작
- `features/search/position.ts` 순수 위치 계산: 아래 기본, 공간 부족 시 위, 좌우는 창 안으로 clamp. 너비는 버튼 너비 이상·최소 220px·창 너비 이하
- 검색 URL 은 기존 `buildSearchUrl`(encodeURIComponent) → `website` 동작으로 바꿔 Rust `web::open_url` 재사용. 브라우저 실행 코드 중복 없음
- `features/hotkeys/guard.ts` P4 실행키용 가드(`shouldHandleDeckHotkey`): 입력 요소 포커스·IME 조합·Ctrl/Alt/Meta·다이얼로그 열림이면 처리하지 않는다
- `scripts/check-search.ts`(`npm run check`) 로 URL 인코딩·위치 계산·가드를 Node 에서 검사
- 남긴 것: 설정에서 사용자 정의 검색엔진 추가 UI (모델·URL 템플릿 처리는 준비됨)

## P4 — 창 동작과 호출 흐름 (완료, 2026-09-17)

- `window.rs` 커서가 있는 모니터의 **작업 영역** 중앙에 표시(물리 px 만 사용, DPI 가 다른 모니터로 옮기면 배치→표시→재배치), 숨김, 토글(보이고 활성이면 숨김). `deck-visibility` 이벤트로 프론트에 알림
- `hotkey.rs` `tauri-plugin-global-shortcut`. 값은 Settings.hotkey 에서 프론트가 `apply_hotkey` 로 넘긴다(하드코딩 없음). 설정이 바뀌면 전부 해제 후 재등록
- `tray.rs` 트레이 아이콘(임시 앱 아이콘) + 메뉴 "QuickDeck 열기 / QuickDeck 종료", 왼쪽 클릭 = 열기. X 버튼은 `closeToTray` 설정에 따라 트레이로 숨김(기본) 또는 종료
- 프론트 `features/hotkeys/keymap.ts` 실행키 ↔ `event.code`(KeyQ/Digit1/Numpad1) 대응, code 가 비면 ASCII key 로 대체. `useDeckHotkeys` 가 `shouldHandleDeckHotkey` 통과 후 버튼을 찾아 마우스 클릭과 같은 `handleRun` 으로 실행(검색 버튼은 팝오버 열기)
- `features/actions/policy.ts` `shouldHideAfterRun(button, settings)` 단일 정책: 전역 hideAfterRun, 미디어·볼륨 6종은 유지. 향후 버튼별 옵션은 이 함수 안에서
- Esc: 다이얼로그 > 입력 요소 blur > 검색 팝오버 > 메뉴 > 덱 숨김 순
- 남긴 것: 포커스 잃으면 숨김(옵션)

## P5 — 설정 화면과 사용자 환경 설정 (완료, 2026-09-17)

- `features/settings/SettingsScreen.tsx` 덱 대신 표시되는 설정 화면(별도 창 없음). 섹션: 호출(단축키·호출 위치) / 창(자동 숨김·항상 위·X 버튼·자동 실행) / 덱(행×열, 격자 밖 버튼) / 검색엔진 / 정보. 변경 즉시 저장·적용. 열려 있으면 실행키 차단(`hotkeysBlocked`), Esc 는 덱으로 복귀
- `HotkeyCapture.tsx` 키를 눌러 등록. `features/hotkeys/accelerator.ts` 가 event.code → accelerator 문자열, 검증(Ctrl/Alt/Win 필수, 기능키 단독 허용, Windows 예약 조합 차단), 표시 문자열. Rust `hotkey.rs` 는 새 조합 등록 실패 시 직전 조합을 되살리고 오류를 돌려주며, 프론트는 성공 시에만 저장
- 스키마 **v2**: `settings.window = { alwaysOnTop, autoStart, hideAfterRun, closeToTray, showAt, lastBounds }`. rememberSize/rememberPosition 제거, `showAt: 'cursor-monitor' | 'last-position'` 추가, `lastBounds` 는 x/y 물리 px + width/height 논리 px. `migrate()` 가 v1 → v2 변환(버튼 데이터 보존). `scripts/check-settings.ts` 로 검사
- 창 크기·위치 기억: Rust 가 Moved/Resized 를 500ms 디바운스해 `deck-bounds` 이벤트 → 프론트 저장 → `apply_window_prefs`. 표시 시 크기는 항상 복원(작업 영역보다 크면 줄임, 최소 200×160), 위치는 showAt 에 따라. 마지막 위치가 어느 모니터에도 없으면 커서 모니터 중앙으로 폴백
- 자동 실행: `tauri-plugin-autostart`(HKCU Run, 인자 `--autostart`). 창은 `visible:false` 로 시작하고 프론트가 `launch_info` 를 보고 자동 시작이 아닐 때만 `show_deck`. 시작 시 실제 등록 상태와 설정값이 다르면 설정값으로 맞춤
- 행/열: 범위 열 2~10, 행 1~6 (`LAYOUT_LIMITS`, `clampLayout`). 줄여서 격자 밖으로 나간 버튼은 **삭제하지 않고 보존**(`hiddenButtons`), 다시 늘리면 복원. 설정에서 목록 확인·명시적 삭제 가능. 격자 밖 버튼은 실행키로 실행되지 않음
- 검색엔진: 기본 3종은 읽기 전용, 사용자 지정 추가/수정/삭제. `validateSearchEngineInput` 이 이름·`{query}` 포함·http(s) URL 을 검사. 버튼이 쓰는 엔진은 삭제 차단 + 사용 버튼 이름 안내
- DevBar 삭제 → `DeckFooter`(⚙ 설정 버튼, 격자 밖 버튼 수). 치수 정보는 `import.meta.env.DEV` 에서만
- 남긴 것: 버튼별 실행 후 유지/숨김, 기본 브라우저·기본 검색엔진 설정 UI(모델은 있음), 애니메이션 토글 UI

## P5 — 아이콘

1. exe/lnk 원본 아이콘 추출 (`SHGetFileInfo`/`ExtractIconEx` → PNG) → `icons/` 저장, `IconRef.extracted`
2. 사용자 이미지: PNG/JPG/WebP/ICO 검증·리사이즈(`image` crate, 최대 256px) → `IconRef.image`; SVG 는 별도 검토
3. 내장 아이콘 세트 (`IconRef.builtin`) — 디자인 단계와 함께
4. `IconView` 가 `convertFileSrc` 로 파일 아이콘 표시, CSP `asset:` 이미 허용됨

색상 테마(라이트/다크/사용자), 버튼 모양, 폰트, 앱 아이콘, 캐릭터. `global.css` 토큰과 `deck.module.css` 만 바꾸면 되도록 구조를 유지한다.

## P7 — 배포

1. `tauri-plugin-updater` + 서명 키(저장소 밖) + `createUpdaterArtifacts: true` + `latest.json` 엔드포인트
2. GitHub Actions 로 태그 → NSIS 빌드 → Release
3. 버전 올리기 스크립트(`package.json`·`tauri.conf.json`·`Cargo.toml` 동시)

## P8 — 실험: 애니메이션 레이어

`features/animation` 에 캐릭터 등장 → 덱 변신 / 실행 → 캐릭터로 축소 애니메이션. 설정 기본값 off. 덱 컴포넌트는 애니메이션 존재를 모른다(레이어가 덱을 감싸는 방식).
