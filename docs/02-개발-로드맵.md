# QuickDeck 개발 로드맵

각 단계는 그 자체로 실행·확인 가능한 상태로 끝나야 한다. 순서는 "먼저 실제로 쓸 수 있게, 그 다음 편하게, 마지막에 예쁘게".

> **현재 상태 (2026-11-09, P11 완료): v0.1.2 실사용 중. P11(기존 창 활성화)은 실사용 검증 뒤 0.1.3 설치본 여부를 결정한다.** 새 대형 기능은 시작하지 않고 폴더·다중 실행을 실제 업무에서 쓰며 버그·불편·반복 행동을 모은다. 퇴근모드 등은 아직 구현하지 않는다.
> 새 대형 기능(루틴·프로필·클라우드·자동 업데이트 등)은 시작하지 않고, 실제 업무 환경에서 QuickDeck 을 일정 기간 쓰면서 버그·불편·반복 행동을 모은다. 수집 항목: 실행이 안 되거나 느린 동작, 자주 손이 가는 설정, 자주 만드는 버튼 종류, 드래그/클릭 오동작, 창 위치·크기 불만.

## P0 — 기틀 (완료, 2026-09-17)

- Tauri 2 + React + TS 프로젝트, 폴더 구조, 데이터 모델, IPC 경계
- 4×3 덱 격자, 빈 슬롯, 임시 버튼, 반응형 치수 계산
- `quickdeck.json` 자동 저장·복원, 스키마 버전·마이그레이션 틀
- Rust 실행기 디스패치 골격 (모두 NotImplemented)

## P1 — 동작 실행기 (Rust) (완료, 2026-09-17)

- `actions/web.rs` 기본 브라우저는 `ShellExecuteW("open", url)`. Edge/Chrome 은 레지스트리 App Paths(HKCU→HKLM→WOW6432Node) 와 일반 설치 위치에서 exe 를 찾아 `Command::new(exe).arg(url)`. 없으면 `BrowserNotFound`
- `actions/shell.rs` `ShellExecuteW` 래퍼(COM 초기화한 전용 스레드). exe/.lnk/파일/폴더 모두 이 경로. 존재 확인을 먼저 해 사용자용 오류로 바꾼다. 인자는 Windows 인용 규칙으로 합침(단위 테스트)
- `actions/system.rs` 미디어·볼륨 `SendInput`, 잠금 `LockWorkStation`, 절전 `SetSuspendState(false)`, 로그아웃/재시작/종료 `shutdown.exe /l | /r /t 0 | /s /t 0`(`power_command` 로 분리해 실행 없이 테스트), 탐색기 `explorer.exe`, 설정 `ms-settings:`, 작업 관리자 `taskmgr.exe`, 캡처 `ms-screenclip:`(실패 시 `snippingtool.exe`)
- 오류: `AppError` 가 `{ message, detail }` 로 직렬화. message 는 그대로 표시, detail 은 콘솔·Rust 로그
- 프론트: `dangerous.ts` 가 `DANGEROUS_SYSTEM_COMMANDS`(로그아웃·재시작·종료) 확인창 문구·버튼명 제공. 성공 시 알림 없음, 실패 시만 붉은 안내. 검색 버튼은 검색어 없이는 Rust 로 보내지 않고 안내만
- 실측 메모: 이 개발 PC 에는 Chrome 이 없어 "찾을 수 없음" 경로만 확인. 잠금·절전·전원 기능은 실행 직전 코드까지만 검증(사용자 수동 확인 예정)

## P3 — 검색 버튼 (완료, 2026-09-17)

- `features/search/SearchPopover.tsx` 검색 버튼에 붙는 fixed 팝오버. 열리면 입력란 즉시 포커스, Enter 검색·Esc 닫기·바깥 클릭 닫기·다른 검색 버튼으로 이동. 매번 새로 마운트되어 검색어는 빈 상태로 시작
- `features/search/position.ts` 순수 위치 계산: 아래 기본, 공간 부족 시 위, 좌우는 창 안으로 clamp. 너비는 버튼 너비 이상·최소 220px·창 너비 이하
- 검색 URL 은 기존 `buildSearchUrl`(encodeURIComponent) → `website` 동작으로 바꿔 Rust `web::open_url` 재사용. 브라우저 실행 코드 중복 없음
- `features/hotkeys/guard.ts` P4 실행키용 가드(`shouldHandleDeckHotkey`): 입력 요소 포커스·IME 조합·Ctrl/Alt/Meta·다이얼로그 열림이면 처리하지 않는다
- `scripts/check-search.ts`(`npm run check`) 로 URL 인코딩·위치 계산·가드를 Node 에서 검사
- 남긴 것: 설정에서 사용자 정의 검색엔진 추가 UI (모델·URL 템플릿 처리는 준비됨)

## P4 — 창 동작과 호출 흐름 (완료, 2026-09-17)

- `window.rs` 커서가 있는 모니터의 **작업 영역** 중앙에 표시(물리 px 만 사용, DPI 가 다른 모니터로 옮기면 배치→표시→재배치), 숨김, 토글(보이고 활성이면 숨김). `deck-visibility` 이벤트로 프론트에 알림
- `hotkey.rs` `tauri-plugin-global-shortcut`. 값은 Settings.hotkey 에서 프론트가 `apply_hotkey` 로 넘긴다(하드코딩 없음). 설정이 바뀌면 전부 해제 후 재등록
- `tray.rs` 트레이 아이콘(임시 앱 아이콘) + 메뉴 "QuickDeck 열기 / QuickDeck 종료", 왼쪽 클릭 = 열기. X 버튼은 `closeToTray` 설정에 따라 트레이로 숨김(기본) 또는 종료
- 프론트 `features/hotkeys/keymap.ts` 실행키 ↔ `event.code`(KeyQ/Digit1/Numpad1) 대응, code 가 비면 ASCII key 로 대체. `useDeckHotkeys` 가 `shouldHandleDeckHotkey` 통과 후 버튼을 찾아 마우스 클릭과 같은 `handleRun` 으로 실행(검색 버튼은 팝오버 열기)
- `features/actions/policy.ts` `shouldHideAfterRun(button, settings)` 단일 정책: 전역 hideAfterRun, 미디어·볼륨 6종은 유지. 향후 버튼별 옵션은 이 함수 안에서
- Esc: 다이얼로그 > 입력 요소 blur > 검색 팝오버 > 메뉴 > 덱 숨김 순
- 남긴 것: 포커스 잃으면 숨김(옵션)

## P5 — 설정 화면과 사용자 환경 설정 (완료, 2026-09-17)

- `features/settings/SettingsScreen.tsx` 덱 대신 표시되는 설정 화면(별도 창 없음). 섹션: 호출(단축키·호출 위치) / 창(자동 숨김·항상 위·X 버튼·자동 실행) / 덱(행×열, 격자 밖 버튼) / 검색엔진 / 정보. 변경 즉시 저장·적용. 열려 있으면 실행키 차단(`hotkeysBlocked`), Esc 는 덱으로 복귀
- `HotkeyCapture.tsx` 키를 눌러 등록. `features/hotkeys/accelerator.ts` 가 event.code → accelerator 문자열, 검증(Ctrl/Alt/Win 필수, 기능키 단독 허용, Windows 예약 조합 차단), 표시 문자열. Rust `hotkey.rs` 는 새 조합 등록 실패 시 직전 조합을 되살리고 오류를 돌려주며, 프론트는 성공 시에만 저장
- 스키마 **v2**: `settings.window = { alwaysOnTop, autoStart, hideAfterRun, closeToTray, showAt, lastBounds }`. rememberSize/rememberPosition 제거, `showAt: 'cursor-monitor' | 'last-position'` 추가, `lastBounds` 는 x/y 물리 px + width/height 논리 px. `migrate()` 가 v1 → v2 변환(버튼 데이터 보존). `scripts/check-settings.ts` 로 검사
- 창 크기·위치 기억: Rust 가 Moved/Resized 를 500ms 디바운스해 `deck-bounds` 이벤트 → 프론트 저장 → `apply_window_prefs`. 표시 시 크기는 항상 복원(작업 영역보다 크면 줄임, 최소 200×160), 위치는 showAt 에 따라. 마지막 위치가 어느 모니터에도 없으면 커서 모니터 중앙으로 폴백
- 자동 실행: `tauri-plugin-autostart`(HKCU Run, 인자 `--autostart`). 창은 `visible:false` 로 시작하고 프론트가 `launch_info` 를 보고 자동 시작이 아닐 때만 `show_deck`. 시작 시 실제 등록 상태와 설정값이 다르면 설정값으로 맞춤
- 행/열: 범위 열 2~10, 행 1~6 (`LAYOUT_LIMITS`, `clampLayout`). 줄여서 격자 밖으로 나간 버튼은 **삭제하지 않고 보존**(`hiddenButtons`), 다시 늘리면 복원. 설정에서 목록 확인·명시적 삭제 가능. 격자 밖 버튼은 실행키로 실행되지 않음
- 검색엔진: 기본 3종은 읽기 전용, 사용자 지정 추가/수정/삭제. `validateSearchEngineInput` 이 이름·`{query}` 포함·http(s) URL 을 검사. 버튼이 쓰는 엔진은 삭제 차단 + 사용 버튼 이름 안내
- DevBar 삭제 → `DeckFooter`(⚙ 설정 버튼, 격자 밖 버튼 수). 치수 정보는 `import.meta.env.DEV` 에서만
- 남긴 것: 버튼별 실행 후 유지/숨김, 기본 브라우저·기본 검색엔진 설정 UI(모델은 있음), 애니메이션 토글 UI

## 실사용 호환성 수정 (2026-09-19)

- **증상**: 학교 PC(Windows 11 Home 26200, 멀티모니터)에서 바탕화면이 활성일 때 Ctrl+Space 로 QuickDeck 이 호출되지 않음. 일반 앱 활성 시에는 정상.
- **확인된 사실**: QuickDeck 을 종료한 채 PowerShell 이 직접 `RegisterHotKey` 로 Ctrl+Space / Ctrl+Shift+Space / Ctrl+Alt+Q 를 등록(모두 성공)하고 바탕화면(`Progman`, explorer) 활성 상태에서 눌렀을 때, 뒤의 두 조합은 WM_HOTKEY 가 도착했지만 **Ctrl+Space 만 도착하지 않았다**. 즉 이 Windows 환경에서는 `Progman` 활성 상태에서 Ctrl+Space 가 RegisterHotKey 등록자에게 전달되지 않는다. QuickDeck 의 `hotkey.rs`·`window.rs`·toggle/show/set_focus 는 원인이 아니며 수정하지 않았다. 원인을 특정 IME 설정으로 단정하지는 않는다.
- **조치**: 신규 설치 기본 단축키 `DEFAULT_HOTKEY` 를 `Ctrl+Shift+Space` 로 변경(저장된 사용자 값은 마이그레이션 포함 어디서도 덮어쓰지 않음, "기본값" 버튼은 새 기본값으로 복원). 설정 화면 단축키 항목에 안내문 추가.
- **부수 관찰(이 개발 PC)**: 알림 센터 등 `ShellExperienceHost` 플라이아웃이 포그라운드일 때는 이벤트는 수신되지만 어떤 프로세스도 `SetForegroundWindow` 에 실패한다(OS 포그라운드 잠금). 플라이아웃을 닫으면 정상. 이 경우 toggle 이 show 만 반복하는 약점이 있으나 이번에는 손대지 않았다.
- 진단 스크립트: `Documents\QuickDeck-diag\quickdeck-fg-probe.ps1`(포그라운드 창 확인), `quickdeck-hotkey-probe.ps1`(전역 단축키 전달 실험). 저장소 밖.

## P6 — 아이콘 시스템 (완료, 2026-09-20)

- **IconRef v3**: `auto | builtin{name} | extracted{file} | image{file} | none`. 스키마 v3 마이그레이션에서 v2 의 `none`(선택 안 함) → `auto`. 버튼·위치·실행키·설정은 그대로. 깨진 아이콘 필드는 `auto` 로 정규화(버튼은 유지)
- **자동(auto)**: 프로그램·파일은 Windows 셸 아이콘(`IShellItemImageFactory::GetImage`, SIIGBF_ICONONLY, 최대 256px) 추출 → `icons/extracted/e_<경로 FNV-1a 해시>.png` 캐시. 폴더·웹·검색·시스템은 내장 아이콘. 추출 실패·원본 없음·캐시 손상은 내장 폴백
- **내장**: Lucide(ISC) `lucide-react` 이름별 import 70개 (`features/icons/builtinNames.ts` 가 단일 목록, `builtin.tsx` 가 컴포넌트 매핑). `currentColor` 라 테마와 분리
- **사용자 이미지**: PNG/JPG/WebP/ICO, 원본 10MB·8192px 이하, 확장자와 실제 내용 둘 다 검사, 256px 안으로 축소한 PNG 사본을 `icons/custom/c_<uuid>.png` 로 복사. SVG 는 스크립트·외부 리소스 위험으로 제외
- **서빙**: Rust 커스텀 프로토콜 `qdicon://` (`http://qdicon.localhost/<id>`), 관리 폴더 안 검증된 파일명만. 404 → `<img onError>` 폴백. CSP `img-src` 에 추가
- **정리**: 설정 → 아이콘 → "지금 정리". 모든 덱의 직접 참조(image/extracted)와 auto 프로그램·파일 경로(→ 캐시 id)를 보존하고 나머지만 삭제. 공유 참조 안전
- **렌더링**: 아이콘 칸 `--icon`(셀 42%) 그대로, `아이콘만` 은 1.3배. 아이콘 `none` + `아이콘만` 이면 이름을 대신 표시. 아이콘 실패는 실행과 무관
- 검사: `scripts/check-icons.ts`(`npm run check`), Rust 19개(실제 셸 추출·이미지 정규화 포함)
- 알려진 제한: 추출 캐시는 무효화하지 않는다(프로그램 아이콘이 바뀌면 정리 후 다시 표시하거나 재등록). 폴더는 특수 폴더 아이콘 없이 내장 폴더. WebP 는 자동 테스트로만 검증(샘플 파일 없음). 브라우저 미리보기에서는 관리 아이콘이 폴백으로 보인다

## P8 — 버튼 드래그 배치 + 아이콘 선택 확장 (완료, 2026-09-20)

**Drag & Drop (Pointer Events 자체 구현, 라이브러리 없음)**

## P9 — QuickDeck 내부 폴더 + 계층형 키보드 탐색 (완료, 2026-10-04)

**개념**: "폴더를 누르면 다른 버튼들이 나온다." QuickDeck 폴더는 앱 안의 버튼 그룹이며, Windows 폴더를 탐색기로 여는 `folder` 동작(UI 라벨 "Windows 폴더")과는 완전히 다르다.

- **모델**: 폴더는 Action 종류 `{ type: 'deck-folder' }` 인 **버튼**이다 (이름·아이콘·실행키·표시 방식·위치를 일반 버튼과 똑같이 가진다). 소속은 `DeckButton.parentId`(루트 = null). 스키마 **v5**; v4 → v5 는 모든 버튼에 `parentId: null` 만 붙인다 → 기존 사용자의 덱은 그대로 루트.
- **왜 새 Action 종류인가**: 편집기·아이콘·실행키·드래그·표시 방식이 "버튼" 하나로 통일되어 있어 별도 엔티티보다 변경이 훨씬 작다. 실행 경로에서는 `App.handleRun` 이 먼저 가로채 navigation 만 하고 `runAction`/Rust 로 보내지 않는다(`runAction` 에도 방어 가드). P10 다중 실행도 같은 방식으로 Action 종류만 더하면 된다.
- **루트 정책**: 덱이 새로 보일 때(`deck-visibility` true)마다 루트에서 시작한다 — 전역 단축키 → 실행키의 위치가 매번 같아야 하므로. 폴더 안에서 실행이 실패해 덱이 남아 있으면 그 폴더에 머문다. 설정 화면 왕복은 현재 폴더를 유지한다.
- **탐색**: 폴더 버튼 클릭 또는 실행키 → 즉시 그 폴더로 (덱 유지, hideAfterRun 무관). 현재 폴더는 state 와 함께 ref 에 기록되어 재렌더 이전의 다음 keydown 에서도 새 폴더의 매핑이 쓰인다. 실측: 전역 단축키 → E → S 를 60/30/0ms 간격으로 넣어도 누락 없음.
- **Esc 우선순위**: 다이얼로그(자체 처리) → 입력 포커스 해제 → 설정→덱 → 검색창 닫기 → 메뉴 닫기 → (드래그 중이면 취소, 캡처 단계) → **폴더 안이면 상위 폴더** → 루트면 숨김.
- **빵부스러기**: 루트가 아닐 때만 격자 위에 얇은 한 줄 `‹ QuickDeck › 학교업무 › 방과후` (상위 항목 클릭 가능, 긴 이름 줄임표, 27px). 루트 화면은 P8 과 동일.
- **컨테이너별 유일성**: 위치(row/col)와 실행키의 중복 금지는 같은 parentId 안에서만. 모든 폴더가 덱의 격자 크기를 공유하고, 격자 밖 보존도 폴더별로 계산한다(설정 화면 집계는 전체).
- **P8 드래그**: 보고 있는 폴더 안에서만 move/swap. 폴더 위에 drop 해 넣는 기능은 만들지 않았다(P9 범위 밖).
- **다른 폴더로 이동**: 편집기의 "위치" 선택(루트 + 폴더 경로 목록, 자기 자신·자손은 비활성). 저장하면 대상 폴더의 **첫 번째 빈 슬롯**으로. 대상에서 실행키가 충돌하면 어떤 버튼과 충돌하는지 알리고 차단, 빈 슬롯이 없으면 차단(격자 밖 위치를 임의로 만들지 않음). action/icon/name/hotkey 유지.
- **삭제**: 버튼이 들어 있는 폴더는 삭제 차단(안내만). 빈 폴더·일반 버튼은 기존대로. cascade delete 없음.
- **cycle·손상 방어**(`repairHierarchy`, load 시): 없는 부모·폴더가 아닌 부모·자기 참조·cycle → 그 버튼만 루트로; 같은 폴더의 중복 위치 → 뒤 버튼을 첫 빈 슬롯(없으면 격자 밖)으로; 중복 실행키 → 뒤 버튼의 키만 비움. 버튼은 절대 버리지 않으며 정상 데이터는 바뀌지 않는다. 경로 계산은 방문 집합으로 무한 루프를 막는다.
- **아이콘**: 자동 = 내장 `folder`. 폴더 버튼에는 우하단에 아주 작은 chevron 만 추가.
- 검사: `scripts/check-folders.ts`(26항목). 실측: 생성/진입/빠른 연속 입력/내부 실행/검색/Esc 체인/중첩/드래그/이동·충돌·꽉 참·cycle/삭제/루트 리셋/설정 왕복/라이트·다크/작은·큰 창.
- 알려진 제한: 폴더 안으로 drag 이동 없음, 폴더별 격자 크기 없음, 키보드로 breadcrumb 조작 없음(Esc 가 기본). 100% DPI 재검증은 이번에 두 번째 모니터가 비활성이라 못 했다(폴더 로직은 DPI 와 무관, 드래그는 P8 에서 100% 검증).

## P10 — 다중 실행 (Multi Action) (완료, 2026-10-04)

**개념**: "여러 버튼을 하나로 묶었다." 사용자 명칭은 **다중 실행**. 등록된 동작을 위에서 아래 순서로 실행할 뿐이며 조건·반복·변수·화면/키 자동화는 없다.

- **모델**: Action 종류 `multi` = `{ steps: MultiStep[], failurePolicy: 'stop' | 'continue' }`, `MultiStep { id, action, delayAfterMs }`. step 은 다른 버튼을 참조하지 않고 **Action 값을 그대로 저장**(스냅샷)한다 — 원본 버튼 삭제·폴더 이동과 무관, 실행 로직 단순. 버튼 자체는 일반 DeckButton 이라 parentId·position·hotkey·icon·display 를 그대로 가진다(루트·폴더 어디든). 스키마 **v5 유지**(구조 변경 없음; `normalizeMultiAction` 이 모양만 고친다).
- **허용 step**: 웹사이트, 프로그램, 파일, Windows 폴더, 시스템 중 즉시 실행형(재생/일시정지·이전/다음 곡·볼륨↑↓·음소거·파일 탐색기·Windows 설정·작업 관리자·캡처 도구).
- **제외 step**: 검색(검색어 입력 필요), QuickDeck 폴더(이동), 다중 실행(중첩 금지), 절전·로그아웃·다시 시작·종료·화면 잠금(세션을 끝내거나 잠가 이후 step 이 무의미). UI 에서 고를 수 없고, 손상 데이터로 들어와도 검증이 막아 **아무 step 도 실행하지 않는다**. 단일 버튼의 위험 기능 확인창 정책은 그대로.
- **delayAfterMs**: step 실행 요청 성공 뒤 다음 step 까지 대기. 0~30,000ms 정수(UI 는 보기 0/0.5/1/2/3/5/10초 + 직접 입력 초). 마지막 step 뒤에는 쓰지 않는다. "실행 완료" 는 Windows 에 실행 요청이 전달된 시점이지 프로그램 로딩 완료가 아니다.
- **failurePolicy**: stop(기본) = 실패한 step 에서 멈춤. continue = 실패를 기록하고 **그 step 의 대기는 생략**한 채 다음 step.
- **러너**(`features/actions/multiRunner.ts`): `for … await execute(step); await delay()` 한 단계씩. setTimeout 을 미리 예약하지 않는다. 실행·대기는 주입받아 검사에서 실제 프로그램을 열지 않는다. step 마다 기존 `runAction` → Rust `execute_action` 경로를 쓴다(Rust 변경 없음).
- **hide 정책**: 전체를 하나의 동작으로 본다. `hideAfterRun=true` 면 시작 즉시 숨기고 백그라운드에서 계속(실측: 숨긴 WebView 에서 1초 간격 4단계가 끝까지 실행됨), false 면 덱을 유지하며 푸터에 "이름 실행 중 (n/N) · 취소".
- **동시 실행**: 한 번에 하나. 같은 버튼 → "이미 실행 중입니다", 다른 다중 실행 → "다른 다중 실행이 진행 중입니다". 일반 버튼은 영향 없음. 덱을 다시 열어도(루트 리셋) 실행은 계속된다.
- **취소**: AbortController 하나. 덱을 다시 열면 푸터의 [취소]. 대기 중에도 즉시 깨어나 **아직 실행하지 않은 step 을 실행하지 않는다**(이미 실행된 프로그램은 되돌리지 않는다). 성공·취소는 조용히 끝난다.
- **실패 알림**: 덱이 보이면 바로 Notice, 숨겨져 있으면 다음에 덱이 보일 때 한 번 보여준다(덱을 강제로 띄우지 않고, 알림 플러그인도 추가하지 않음). 문구: 이름 · 실패 step 번호 · step 요약 · 기존 오류 메시지 · (stop 이면) "이후 동작은 실행하지 않았습니다".
- **편집기**(`MultiStepsEditor`): 번호 카드(제목=이름/호스트/기능, 종류, 대기), 카드 클릭으로 펼쳐 내용 편집, ↑↓ 순서, 삭제(즉시, draft), [+ 동작 추가]는 허용 종류만, 실패 시 세그먼트. 1~20개. 모든 변경은 draft 에만 — [취소] 는 원본 불변, [저장] 에 한 번 반영.
- **아이콘**: 자동 = 내장 `zap`(번개). IconRef 그대로.
- **P8/P9**: 일반 버튼과 같은 규칙으로 드래그·폴더 이동·컨테이너별 위치/실행키. 이동·교환 뒤 steps 보존.
- 검사: `scripts/check-multi.ts`(40항목). 실측: 생성/편집/취소 불변/저장, 마우스·실행키 실행, 숨긴 상태 순차 실행과 간격, 취소·대기 중 취소, stop/continue, 중복 실행 안내, 폴더 안 다중 실행을 전역 단축키 → S → Q 로, 드래그·교환·짧은 클릭=실행, 재시작 유지, 라이트/다크/작은 창 편집기.
- 알려진 제한: 중첩 다중 실행 없음, 프로그램이 뜰 때까지 기다리는 기능 없음(대기 시간으로 보완), 다중 실행 동시 실행 1개, 진행 UI 는 푸터 한 줄, 실행 중 앱을 완전히 종료하면 남은 step 은 실행되지 않음(정상).

## P11 — 기존 창 활성화 및 중복 실행 방지 (Activate-or-Launch) (완료, 2026-11-09)

실사용에서 나온 개선: 이미 열려 있는 프로그램·Windows 폴더·파일을 버튼으로 누르면 새로 열지 않고 **기존 창을 앞으로** 가져온다. 원칙은 **"엉뚱한 창을 활성화하는 것보다 중복 실행이 낫다"** — 확실히 식별한 창만 활성화하고 그 외에는 기존 `ShellExecuteW` 경로 그대로.

- 구현: Rust `actions/activate.rs`. `execute()` 가 Program/File/Folder 에서 먼저 `activate_*` 를 부르고 `NotFound` 일 때만 기존 실행. 인자가 있는 Program 은 활성화하지 않는다. 다중 실행 step 도 같은 `execute` 를 쓰므로 자동 적용. 데이터 모델·스키마·UI 변경 없음, 새 실행 옵션은 두지 않았다(실사용 결과를 본 뒤 결정).
- **프로그램**: `EnumWindows` 로 보이는 최상위 창(소유자 없음·도구창 아님·DWM cloaked 아님)의 소유 프로세스 **실행 파일 경로**(`QueryFullProcessImageNameW`) 를 등록 경로와 비교(소문자·구분자·끝 구분자 정규화). 이름만 같은 다른 exe 는 다른 프로그램. Z 순서 맨 앞의 제목 있는 창을 대표로. `.lnk` 는 `IShellLink` 로 대상 exe 를 풀되 **인자가 있으면 활성화하지 않고 기존 실행**.
- **Windows 폴더**: `ShellWindows`(COM) 가 보고하는 탐색기 창의 `LocationURL`(file URL → 경로) 을 등록 폴더와 비교. 창 제목은 쓰지 않는다. UNC/정션/심볼릭 링크의 동일성은 다루지 않는다(불일치면 기존 실행).
- **파일**: ① Running Object Table 에 **정확한 전체 경로**가 등록되어 있고 ② 같은 파일 이름이 다른 경로로도 열려 있지 않고 ③ 연결 프로그램이 Excel/Word/PowerPoint 이며 ④ 그 프로세스의 창 중 제목이 "문서이름 - 앱"(상태 접미 허용) 인 창이 **정확히 하나**일 때만 활성화. 그 외(메모장·PDF·HWP 등)는 기존 실행.
- **활성화**: 최소화면 `SW_RESTORE` → `SetForegroundWindow` → 실제 포그라운드 확인 → 안 되면 입력 큐를 붙여 한 번 더. QuickDeck 은 사용자가 방금 입력한 프로세스라 보통 허용된다. 확인이 안 돼도(모달 대화상자 등) **창을 찾은 이상 새로 실행하지 않는다**(`ActivationRequested`). 활성화 성공은 "성공한 동작"이라 hideAfterRun 정책이 그대로 적용된다.
- 성능: 실행 시점에만 한 번 탐색(폴링 없음). 실측 프로그램 활성화 6~8ms, 폴더 32~39ms.
- 권한: `PROCESS_QUERY_LIMITED_INFORMATION` 만 사용. 관리자 권한 프로세스의 창은 경로를 읽지 못하면 후보에서 빠진다(기존 실행으로).

**파일 활성화 지원 표 (2026-11-09 실측)**

| 파일/앱 | 정확한 기존 창 감지 | 동작 |
|---|---|---|
| XLSX / Excel | 가능 (ROT 경로 + 창 제목) | activate |
| DOCX / Word | 가능 (ROT 경로 + 창 제목) | activate |
| PPTX / PowerPoint | 같은 규칙(코드상 허용), 실측 미완 | activate(규칙 충족 시) |
| TXT / Windows 11 메모장(Store) | 불가 (경로 정보 없음) | ShellExecute fallback (메모장이 탭을 스스로 처리) |
| PDF / Edge | 불가 | ShellExecute fallback |
| HWP / 한글 | 미검증(샘플 없음) → 미지원 목록 | ShellExecute fallback |
| 같은 이름의 파일이 다른 폴더에서도 열림 | 구분 불가 → 활성화 금지 | ShellExecute fallback |

알려진 제한: Windows 11 의 `System32\notepad.exe`·`calc.exe` 같은 **앱 실행 별칭**은 실제 프로세스(Store 앱) 경로가 달라 기존 창을 찾지 못하고 기존대로 실행된다(앱이 스스로 처리). 프로그램 창이 여러 개면 가장 앞(최근) 창 하나만 활성화한다. 이 PC 의 .xlsx 는 연결 프로그램 설정이 비어 있어 ShellExecute 가 "연결 프로그램" 대화상자를 띄우는데 이는 환경 문제이며 P11 과 무관하다. 브라우저 탭 중복 감지는 하지 않는다.
